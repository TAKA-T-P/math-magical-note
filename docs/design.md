# 動く魔法のノート 設計書（Ver.0.1 / MVP 第1段階）

仕様書 Ver.1.0 の「11. 開発の進め方」に従い、まず画面構成・コンポーネント構造・問題データ形式を定め、
代表1問（問1.2(1)）で解説表示・手書き・操作系を完成させた段階の設計です。

---

## 1. 技術構成と選定理由

| 項目 | 採用 | 比較した候補と理由 |
|---|---|---|
| 言語・UI | HTML / CSS / 素の JavaScript（ESモジュール） | React 等も検討したが、画面数が少なく状態も単純なため不要。依存を減らし、長期保守と教材担当者の参加を容易にする |
| 開発・ビルド | Vite | 設定ほぼ不要、教材データを単元ごとに自動で分割読み込みできる（`import.meta.glob`） |
| 数式 | KaTeX | MathJax より高速・軽量で、段階表示のたびに再描画しても遅れない。`\htmlClass` で数式の一部にキーを付けられ、部分強調に使える |
| 手書き | Canvas（Pointer Events） | マウス・ペン・タッチを同じ処理で扱える |
| 図形・グラフ | （未実装）SVG、必要に応じ JSXGraph | 4-3 の拡張時に `lab` 種別＋専用ブロックとして追加する |
| データ | JSON（単元＝節ごとに1ファイル） | |
| 公開 | 静的ファイル（GitHub Pages 等）。ハッシュ方式のURLで再読み込みしても壊れない | |
| オフライン | 簡易サービスワーカー（一度開いたリソースをキャッシュ） | |

## 2. 画面構成

```
ホーム (#/)
 ├─ 学年選択（中1・中3は「準備中」で無効）
 ├─ 章の選択 → 章・節選択画面 (#/units/g2/c2)
 │                 └─ 節ごとの教材カード（ポイント・問題、ページ番号・タグ付き）
 │                       └─ 授業画面 (#/lesson/g2/c2/s1/<コンテンツID>)
 ├─ 最近開いた単元（最大5件）
 ├─ 授業モード開始（前回の教材を開く）
 ├─ 設定 (#/settings)
 └─ ヘルプ (#/help)
```

### 授業画面（1600×900 の固定ステージを画面に合わせて拡大縮小）

```
┌ ヘッダー ───────────────────────────────────────────────┐
│ 中2数学 › 第2章 連立方程式 › 第1節 …     [定期] 問1.2(1) [p.25] [‹][›] │
├ 本文（グリッド：top / left・right / bottom）──────────────────────┤
│ top   : 問題文・連立方程式                                           │
│ left  : 筆算など                │ right : 代入・答えなど              │
│ bottom: ヒント／ステップの補足コメント                                 │
├ 操作ボタン ─────────────────────────────────────────────┤
│ [一覧][最初][前へ] 3/9 縦にそろえて書く [次へ] │問題│ヒント│解説│全解答│ [手書き][講師][全画面][設定] │
└──────────────────────────────────────────────────────┘
  手書きレイヤー（Canvas）はステージ全体に重なる。パレットは右端に縦表示。
  講師用メモは右からのパネル（ボタンを押したときだけ表示）。
```

- 内部座標は常に 1600×900。PC（1366×768 など）でも電子黒板（1920×1080、4:3 など）でも同じ見た目になり、余白は黒帯になる。
- そのため **手書きの位置が画面サイズによって問題とずれない**（ストロークもステージ座標で保存）。
- 本文がはみ出した場合はコンソールに警告し、オレンジの破線枠を表示する（データ作成時の確認用）。

## 3. ソース構成

```
src/
  main.js               ルート登録・起動
  app/
    router.js           ハッシュ方式ルーター
    settings.js         設定の保存（localStorage: mmn.settings.v1）
    catalog.js          学年→章→節カタログと、節データの遅延読み込み・年度選択
  math/
    katex-config.js     KaTeX 設定と \hl マクロ（検証スクリプトと共用）
    render.js           数式・教材文章の HTML 化
  lesson/
    state.js            表示モード・ステップの状態遷移と「表示内容」の計算（DOM非依存）
    renderer.js         ブロックの表示テンプレート・段階表示・強調・矢印
    ink.js              手書きレイヤー
  views/                home / units / lesson / settings / help
  ui/                   アイコン・ダイアログ・全画面
  data/
    catalog.json        学年・章・節・教材ページ（年度別）
    g2/c2/s1.json       中2 第2章 第1節 の教材データ
scripts/validate-data.mjs  教材データの検証（ビルド時に自動実行）
```

**状態（state.js）と表示（renderer.js）を分離** しているのは、将来
「講師用PCウィンドウ」と「電子黒板の生徒用ウィンドウ」を分けるときに、
状態だけを `BroadcastChannel` で同期すれば済むようにするため。家庭学習モードも同じ state.js を使う。

## 4. 教材データ形式

### 4-1. カタログ（`src/data/catalog.json`）

```jsonc
{
  "editions": ["2026"],           // 対応している教材年度
  "grades": [{
    "id": "g2", "label": "中2", "enabled": true,
    "chapters": [{
      "id": "c2", "number": "第2章", "title": "連立方程式", "pages": { "2026": 24 },
      "sections": [
        { "id": "s1", "number": "第1節", "title": "加減法による解き方",
          "pages": { "2026": 24 }, "data": "g2/c2/s1" }   // data があれば教材あり
      ]
    }]
  }]
}
```

ページ番号は `pages: { 年度: ページ }` で持つため、年度ごとのページ変更はここだけ直せばよい。

### 4-2. コンテンツ（`src/data/g2/c2/s1.json` の `contents[]`）

| 項目 | 内容 |
|---|---|
| `id` | 一意のコンテンツID。**ページ番号・問題番号を含めない**（例 `g2.simul.elim.q-add-1`）。一度付けたら変えない |
| `rev` | 内容の版。年度で内容が変わったら、同じ `id` で `rev` を上げた別オブジェクトを追加し、`editions` で使い分ける |
| `editions` | 年度ごとの掲載情報 `{ "2026": { page, number, tags, ref } }` |
| `type` | `title`（章タイトル）/ `point`（ポイント解説）/ `exercise`（例題・演習）/ `similar`（類題）/ `advanced`（発展）/ `lab`（図形・グラフ実験） |
| `title` | 内容を表す短い名前 |
| `statement` | 問題（ステップ0）で表示するブロックの配列 |
| `steps` | 解説ステップの配列（下記） |
| `hints` | ヒント文の配列（最終解答は書かない） |
| `answer` | 正答（`tex` と、数値なら `values`） |
| `check` | 検算用。`equations`（もとの式）・`solution`（解）・`derived`（途中式）を登録すると、ビルド時に解で成り立つか自動確認する |
| `teacher` | 講師向け情報：`aim` 指導のねらい / `questions` 発問例 / `pitfalls` つまずき / `commonErrors` よくある誤答 / `notes` 補足 / `procedure` 推奨手順 / `status`（`draft` なら「下書き・要確認」と表示） |

### 4-3. ブロック（表示テンプレート）

| `type` | 用途 | 主な項目 |
|---|---|---|
| `text` | 文章 | `text` |
| `math` | 数式（LaTeX） | `tex` |
| `callout` | 赤枠の注意・判断 | `text`, `tone` |
| `answer` | 答えの枠 | `tex` |
| `pointbox` | 教材の「ポイント」囲み | `title`, `items[]`（`text`, `note`, `strong`, `contIndent`） |
| `title-card` | 章タイトルと節一覧 | （カタログから自動生成） |

共通項目：`id`（必須）、`area`（`top` / `left` / `right` / `bottom`）、`size`（`s` / `m` / `l`）、
`inline`（横に並べる）、`hide`（最初は隠しておくキー）。

文章中の書式：`$...$` 数式、`**語句**` 赤太字、`__語句__` 下線、`{{key|語句}}` キー付き語句（穴埋めにできる）。

### 4-4. キーと段階表示

数式・文章の一部に **キー** を付け、ステップからそのキーを強調・表示する。

```latex
\hl{y1}{+3y}            % 「+3y」にキー y1（符号の前後の空白は自動）
\hl{cy1}{+\mkern4mu 3y} % 筆算のセル先頭の符号は空白を補う
```

ステップの項目：

| 項目 | 内容 |
|---|---|
| `id`, `title` | ステップID と見出し（操作内容。操作バーに表示） |
| `add` / `remove` | 追加・削除するブロック（「不要な部分の消去」） |
| `reveal` | `hide` していたキーを表示する（途中式を1行ずつ出す。レイアウトがずれない） |
| `emphasis` | `{ key, style, color, persist }`。style は `color`（色変更）/ `box`（囲み）/ `marker`（ハイライト）/ `strike`（消去線）/ `dim`（薄く）。`persist: true` で以降のステップでも残す |
| `arrows` | `{ from, to, label, color }` キーからキーへの矢印（代入など） |
| `anim` | 追加ブロックの登場方法：`fade` / `slide-up` / `slide-left` / `none` |
| `comment` | 生徒向けの補足コメント（画面下部） |
| `teacherNote` | 講師用メモにだけ表示する指導ポイント |

アニメーションは **登録済みの正しい式を順に見せるだけ** で、式を変形する演出は行わない（誤った式変形に見えないため）。

### 4-5. 表示モード

| モード | 内容 | → キー |
|---|---|---|
| 問題 | statement のみ | 解説のステップ1へ |
| ヒント | 問題＋ヒント（1つずつ追加） | 次のヒント |
| 解説 | ステップ 0〜N を1つずつ | 次のステップ |
| 全解答 | 全ステップを一括表示 | — |

## 5. 設定（localStorage `mmn.settings.v1`）

教材年度・アニメーション速度（なし/速い/標準/遅い）・表示倍率・操作ボタンの自動非表示・
別の問題に移るときの手書き（たずねる/消去/残す）・ペンの色/太さ/種類・前回の教材・最近開いた教材。
学習履歴は将来 `mmn.history.v1` など **別キー** に保存し、設定と混ぜない。

## 6. 問題を追加する手順

1. 教材PDFで問題文・数式・解答を確認する（年度版を正本とする）。
2. 該当する節の JSON（なければ新規作成し、`catalog.json` の節に `"data"` を追加）に `contents` を追加する。
3. `check` に元の式・解・途中式を登録する。
4. `npm run validate` で検証（数式の構文、キーの参照、検算）。ビルド時にも自動で実行され、エラーがあるとビルドが止まる。
5. `npm run dev` で授業画面を開き、全ステップを目で確認する（はみ出しはオレンジ枠で分かる）。
6. 講師向け情報は、教材にない内容を書いた場合 `status: "draft"` のままにし、確認後に外す。

特殊な演出（グラフ・図形など）が必要な場合だけ、`renderer.js` の `BLOCK_BUILDERS` にブロック種別を追加する。

## 7. 今後の拡張に向けた設計上の配慮

- **講師用・生徒用ウィンドウ分離**：state.js の状態を BroadcastChannel で同期し、生徒用ウィンドウでは講師パネルを生成しない。
- **家庭学習モード**：同じ教材データと state.js を使い、`answer.values` で正誤判定、履歴は別ストレージ。
- **グラフ・図形**：`lab` 種別と `graph` / `figure` ブロック（SVG または JSXGraph）を追加。キーと emphasis の仕組みはそのまま使える。
